# Codebook

Understand an actual project's code through standard editor AI chat, real execution and the native debugger in **VS Code and Cursor**. Save an explained code path as learning material, or independently generate a repository-wide DeepWiki site.

## Product features

| Feature                                 | Experience                                                                                                                                                                                                                                                                                   |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Live explanation                        | Ask `/codebook` in Copilot Chat or Cursor Agent. The AI operates the real application/runtime, pauses actual source, explains in chat and continues. Inspect values in the native debugger.                                                                                                  |
| Learning replay / time-travel debugging | Replay the application, the source executing at that time and historical values/stack in the native debugger in sync. Repeatedly step backward/forward and seek after runtime exit. The live chat area becomes a learning summary with a sequence diagram.                                   |
| Independent LLM Wiki / DeepWiki         | Reproduce DeepWiki itself through the editor AI's generation skill: full chapters, diagrams, source citations, reader navigation and repository Q&A. Keep local/configurable output, chat/browser updates and source links into your editor. Runtime/debug MCP and learning are independent. |

The owner retired the three selectable UI themes, not these distinct feature screens. Codebook Activity Bar navigation reaches them. The [v9 product image](DESIGN.md) is owner-approved after GStack design review. Implementation follows the local [execution guide and acceptance map](IMPLEMENTATION.md), reached from AGENTS.md, with mandatory visual inspection.

## Implementation status

This is a private preview, not a Marketplace or Open VSX release. The delivered version is **0.2.30.0** once [PR #88](https://github.com/laststance/codebook/pull/88) is merged; until then 0.2.29.0 is the delivered one and 0.2.30.0 the candidate that pull request holds, and [PROJECT_STATE.md](PROJECT_STATE.md) says where the delivery stands. It is the delivery of [Cycle 0046](docs/cycles/0046-carried-defects-of-cycle-0045.md): a bug-fix cycle with no increment that closes the 46 defects Cycle 0045 left and the 461 found while it ran ([the list](docs/cycles/0046-carried-defects.md)). Among them is a security defect of 0.2.29.0, which followed a link at the path of the Wiki update marker's claim and deleted files of the folder the link led to. A storage lock, its claim and the Wiki update marker are now judged by the start of their owner's process, a VS Code Wiki update sends its request into a chat of its own, and the MCP API is 1.7, which answers a source's lines once. Its native checks ran on pre-release builds in VS Code 1.140.0 and Cursor 3.23.12 for Linux, shown through WSLg on a Windows host; an editor for Windows, macOS and the real Cursor Agent CLI were not observed, and every native observation is bounded development evidence for the build its record names, not acceptance. The cycle must close with nothing carried forward, so the cycle after it is a feature cycle that starts clean; the proof that a natural `/codebook` request reaches its observed result on its first admitted run is still owed and belongs to that cycle's frozen request. What each earlier cycle delivered, with its tests, trials and limits, is in the [change history](CHANGELOG.md) and in that cycle's record under [`docs/cycles`](docs/cycles); [PROJECT_STATE.md](PROJECT_STATE.md) holds the verified scope and the open gaps.

The specification is [goal version 10](PRODUCT_GOAL.md), and the implementation targets external repositories. Historical fixture or coupled-Wiki success is not proof of that destination.

Until final acceptance begins, actual-editor development verification uses the owner-designated [nextjs-dashboard checkout](DEVELOPMENT.md#required-development-target-before-acceptance). Final acceptance requires [all nine designated projects in two stages](docs/acceptance/FINAL_REVIEW.md), both editors and every applicable runtime use case. No Stage 1 or Stage 2 PASS is claimed under goal version 10 or under version 9 before it.
