# Codebook

Understand an actual project's code through standard editor AI chat, real execution and the native debugger in **VS Code and Cursor**. Save an explained code path as learning material, or independently generate a repository-wide DeepWiki site.

## Product features

| Feature                                 | Experience                                                                                                                                                                                                                                                                                   |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Live explanation                        | Ask `/codebook` in Copilot Chat or Cursor Agent. The AI operates the real application/runtime, pauses actual source, explains in chat and continues. Inspect values in the native debugger.                                                                                                  |
| Learning replay / time-travel debugging | Replay the application, the source executing at that time and historical values/stack in the native debugger in sync. Repeatedly step backward/forward and seek after runtime exit. The live chat area becomes a learning summary with a sequence diagram.                                   |
| Independent LLM Wiki / DeepWiki         | Reproduce DeepWiki itself through the editor AI's generation skill: full chapters, diagrams, source citations, reader navigation and repository Q&A. Keep local/configurable output, chat/browser updates and source links into your editor. Runtime/debug MCP and learning are independent. |

The owner retired the three selectable UI themes, not these distinct feature screens. Codebook Activity Bar navigation reaches them. The [v9 product image](DESIGN.md) is owner-approved after GStack design review. Implementation follows the local [execution guide and acceptance map](IMPLEMENTATION.md), reached from AGENTS.md, with mandatory visual inspection.

## Implementation status

This is a private preview, not a Marketplace or Open VSX release. The delivered version is **0.2.28.0**, delivered by [Cycle 0044](docs/cycles/0044-wiki-update-and-carried-defects.md) through [PR #84](https://github.com/laststance/codebook/pull/84): **Update LLM Wiki** ends with a result the learner can see on the Wiki page and in the editor, and the 440 defects that Cycles 0031 to 0043 had left open are closed (270 by a fix with a test that fails without it, 169 by recorded evidence, one on the pull request). It is the first delivery under the [cycle rule](AGENTS.md#cycle-rule-every-carried-defect-is-fixed-in-the-next-cycle). Its installed trials ran on pre-release builds in VS Code 1.140.0 and Cursor 3.23.12 for Linux, shown through WSLg on a Windows host; a running and a succeeding update in Cursor were not observed, and every native observation is bounded development evidence for the build its record names, not acceptance. [Cycle 0045](docs/cycles/0045-natural-request-and-carried-defects.md) is open: it submits the frozen natural `/codebook` request once per editor, fixes what stops its first run and takes the 222 defects Cycle 0044 left. What each earlier cycle delivered, with its tests, trials and limits, is in the [change history](CHANGELOG.md) and in that cycle's record under [`docs/cycles`](docs/cycles); [PROJECT_STATE.md](PROJECT_STATE.md) holds the verified scope and the open gaps.

[Cycle 0029](docs/cycles/0029-feature-specification.md) updates the specification to [goal version 9](PRODUCT_GOAL.md). The implementation now targets external repositories. The Study pane's retired presentation selector and duplicate custom value display are removed; the **Codebook: Select Presentation** command is removed too, and `codebook_presentation` selects only the Study workspace layout (a Living book or Guided walkthrough layout that a saved preference already shows stays until the learner changes it). The specified learning replay and independent Wiki remain implementation work. Historical fixture or coupled-Wiki success is not proof of the new destination.

Until final acceptance begins, actual-editor development verification uses the owner-designated [nextjs-dashboard checkout](DEVELOPMENT.md#required-development-target-before-acceptance). Final acceptance requires [all nine designated projects in two stages](docs/acceptance/FINAL_REVIEW.md), both editors and every applicable runtime use case. No version 9 Stage 1 or Stage 2 PASS is claimed.
