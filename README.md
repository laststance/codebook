# Codebook

Understand an actual project's code through standard editor AI chat, real execution and the native debugger in **VS Code and Cursor**. Save an explained code path as learning material, or independently generate a repository-wide DeepWiki site.

## Product features

| Feature                                 | Experience                                                                                                                                                                                                                                                                                   |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Live explanation                        | Ask `/codebook` in Copilot Chat or Cursor Agent. The AI operates the real application/runtime, pauses actual source, explains in chat and continues. Inspect values in the native debugger.                                                                                                  |
| Learning replay / time-travel debugging | Replay the application, the source executing at that time and historical values/stack in the native debugger in sync. Repeatedly step backward/forward and seek after runtime exit. The live chat area becomes a learning summary with a sequence diagram.                                   |
| Independent LLM Wiki / DeepWiki         | Reproduce DeepWiki itself through the editor AI's generation skill: full chapters, diagrams, source citations, reader navigation and repository Q&A. Keep local/configurable output, chat/browser updates and source links into your editor. Runtime/debug MCP and learning are independent. |

The owner retired the three selectable UI themes, not these distinct feature screens. Codebook Activity Bar navigation reaches them. The [v9 product image](DESIGN.md) is owner-approved after GStack design review. Implementation follows the local [execution guide and acceptance map](IMPLEMENTATION.md), reached from AGENTS.md, with mandatory visual inspection.

Codebook contributes `debug.focusEditorOnBreak: false` as the native debugger default, so a breakpoint can select its source and values without moving the keyboard out of the chat. This default applies to native debugging throughout editors where Codebook is enabled. At a stop Codebook did not cause (a step or a continue of yours, a refresh of the debug adapter, or a debug session that is not a Codebook run), Codebook gives the paused file the keyboard once, as the editor would without this default; it does nothing while a recording is open or when you set the setting yourself. Existing explicit User and Workspace preferences take precedence; Codebook writes no settings file. Set `debug.focusEditorOnBreak` to `true` in the ordinary editor settings if you prefer the debugger to focus source at a break. Disabling or removing Codebook removes its default contribution.

## Implementation status

This is a private preview, not a Marketplace or Open VSX release. The delivered version is **0.2.31.0** once [PR #91](https://github.com/laststance/codebook/pull/91) is merged; until then 0.2.30.0 is the delivered one and 0.2.31.0 the candidate that pull request holds, and the current state in the active cycle's record says where the delivery stands. It is the delivery of [Cycle 0047](docs/cycles/0047-carried-defects-of-cycle-0046.md): a bug-fix cycle with no increment that closes the 53 defects Cycle 0046 left and the 226 found while it ran ([the list](docs/cycles/0047-carried-defects.md)). Most of them are in the Wiki: the reader now bounds the memory and the time that a page can take, and reads a page that a cloned repository crafted as each browser can read it; the skill's publisher takes a lock for each publish, keeps its records small and judges a stopped publish by the computer it ran on. The MCP API stays 1.7. The adversarial review of its final candidate found defects that this version does not fix; by the owner's direction they go to Cycle 0048, a bug-fix cycle whose pull request holds only their fixes, and the feature cycle after it starts clean; the proof that a natural `/codebook` request reaches its observed result on its first admitted run is still owed and belongs to that feature cycle's frozen request. What each earlier cycle delivered, with its tests, trials and limits, is in the [change history](CHANGELOG.md) and in that cycle's record under [`docs/cycles`](docs/cycles); the active cycle's record holds the verified scope and the open gaps in its current state.

The specification is [goal version 10](PRODUCT_GOAL.md), and the implementation targets external repositories. Historical fixture or coupled-Wiki success is not proof of that destination.

Until final acceptance begins, actual-editor development verification uses the owner-designated [nextjs-dashboard checkout](DEVELOPMENT.md#required-development-target-before-acceptance). Final acceptance requires [all nine designated projects in two stages](docs/acceptance/FINAL_REVIEW.md), both editors and every applicable runtime use case. No Stage 1 or Stage 2 PASS is claimed under goal version 10 or under version 9 before it.
