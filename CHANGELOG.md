Cycle 0051 ([Issue #122](https://github.com/laststance/codebook/issues/122)): a test replay opens in the learning-replay composition a browser replay has, with the Learning summary in the chat's place, one transport for both replay families, and a Learning summary button that shows a hidden summary again (approved choice 5A).

**A test replay in the learning-replay composition.**

- **Open replay and Saved studies** open a test replay as a browser replay opens: the Study pane closes, the Application pane shows the recorded test output above the recorded-source tab, Run and Debug shows the recorded stop, and the **Learning summary** stands in the chat's place. In VS Code the summary moves once into the chat's side bar; in Cursor it keeps its own container and offers Move View. Opening a replay during a live run leaves the Live arrangement for it, and Return to Live gives the Live arrangement back.
- **The latest choice wins.** Two Open replay presses, or a test replay chosen while another one is opening, open the replay you chose last, and an answer to an earlier one-replay-at-a-time notice closes nothing.
- **A failed open** gives the Study pane back on Saved studies and tells the failure once, with its Saved studies sentence.
- **An agent cannot open a test replay**: `codebook_playback` still refuses it, and the chat asks you to open it from Open replay or Saved studies.

**The Learning summary of a test replay.**

- **One reading order.** The test's file and title path, the learning title, the result, the capture and its reason, the question and the processing summary, the sequence diagram, then the moment: a `Step <n> · <label>` heading, its position, explanation and lines, the values hint, **I understand this test history** and the event list.
- **The selected step is marked on the diagram** in the link color, bold and underlined, and the mark moves with the replay without redrawing the diagram, so its scroll position stays. An output or the result marks no step.
- **Long texts stay short.** The question, the summary and the capture reason show at most three lines with **Show more**, which shows the whole text in place, and the diagram scrolls inside its own region.

**One transport for both replay families.**

- **The bottom panel reads Learning replay** during a test replay and shows the transport alone; with the bottom panel hidden, the transport stands at the foot of the summary.
- **A test replay's controls**: Replay from start, Previous stop, Play, Next stop, the slider with its coverage marks and a `<t> s / <total> s` readout, and **Previous event** and **Next event** for outputs and the result. Replay from start, Home and End reach the first and last event from any page of the event list, also when several events share one time.
- **Keys on the focused slider**: for a test replay, ← and → move by event, Page Up and Page Down by stop, Home and End to the first and last event; the browser replay's keys are unchanged. The Keyboard shortcuts list names both sets.
- **The status line** reads `Test replay playing` or `Test replay paused` and names a refused or failed move; when the replay debugger does not start on a move, it says the last moment is still shown and how to restart it.

**Hiding and showing the Learning summary (5A).** The transport's status row ends with a **Learning summary** button for both replay families: it shows a summary you hid, collapsed or whose container you closed, and brings the keyboard to a shown one. The moment, the replay debugger's frame and the summary's scroll position stay, a playing replay goes on playing, and the keyboard returns to the control the summary last held.

**Compatibility.** The MCP API stays 1.8, the bundled skill is unchanged and no stored format changes.

**Checked so far.** The host and Reader DOM tests above. A native smoke check in VS Code 1.142.0 and Cursor 3.27.12 on macOS ran on a development candidate of this branch; the native round of this release's candidate (N51) is recorded in [Issue #122](https://github.com/laststance/codebook/issues/122). ## [0.2.38.0] - 2026-10-24 (development candidate)

Cycle 0050's third pull request ([Issue #118](https://github.com/laststance/codebook/issues/118)): a test replay's recorded-source tab and the moves between its moments, opening a replay, Cursor's Learning summary, the browser replay's frames, and a repository-browser run on the project's own port. With it, every defect Cycle 0049 carried is fixed or closed with evidence.

**The recorded-source tab of a test replay.**

- **One tab follows the selected stop.** `Captured-<file>` shows the source that ran at the stop, with the stopped line, an end-of-line label and a CodeLens above the line that carries the whole `Recorded: <path>:<line> · <time> s`. Files of the same name in different folders get their own tab. At an output or the result the tab shows its placeholder from the first line, and Focus source brings the tab forward. A recorded path cannot turn into a link or an icon in the hover or the CodeLens.
- **The tab ends with its replay.** Closing the Study workspace or opening a browser recording closes it, and a pinned tab of a retired replay shows the placeholder, not the last stop.
- **A test replay opened over a browser replay** closes the captured-source tabs that replay had open when you left it, once. Your own files, a pinned or edited tab, and a tab you open afterwards stay, also at the same address; a tab the editor refuses to close is told, and its close is tried again at the next stop.

**Moving between moments.**

- **Every surface leaves the earlier moment together.** At Next stop, Previous stop, a seek or Play, the position line and the playback time already name the requested moment and say `loading…` until it is shown, the event list marks its row, the debugger empties, and the earlier stop's CodeLens and call stack never stand beside another moment's source.
- **Slow or failed moves stay usable.** One 5-second deadline bounds a recorded-source tab's show; Play pauses at a stop whose tab cannot open, and Retry shows that moment again without restarting a replay debugger you stopped. A move you overtake or withdraw leaves only the newest moment on every surface, and selecting a stop again while an output is still being shown shows the stop.

**Opening a replay.**

- **Open replay right after a live run** opens the Study pane with its transport, also beside Cursor's Agent, and an empty main editor beside Cursor's Agent is arranged without a click.
- **No article lines beside a test replay.** The Study pane hides the Repository article's source tab, its `Current source unavailable` lines and its flow while a test replay is selected (a keyboard focus that stood on them moves to the test replay's transport), and the Test replay section scrolls into view once when the replay opens.
- **A file open as a preview tab** no longer stops Open replay. When a destination is still blocked, a dialog names the tab and offers **Keep Tab Open** or **Close Tab**; a tab the editor cannot keep open is told once and written to Output › Codebook.
- **Restore Study workspace layout** with a test replay selected brings the recorded-source tab back to the front without taking the keyboard and gives the grid its sizes back; when it cannot, the Study pane says why, once.
- **Output › Codebook records why a placement was refused** (`presentation:placement-refused`, `presentation:focus-unreported`): the groups and tabs before and after, and the editor's events.

**Cursor's Learning summary.** In Cursor the Learning summary has its own Activity Bar container, with no contribution error. In VS Code it moves once into the chat's side bar at your first replay open, and a view you moved yourself is never moved back.

**The browser replay.** Stepping between stops no longer shows dark frames or `Canceled`: the shown frame stays until the next one is ready, also on a seek. The recorded-source label leaves together with the stopped line.

**Test stops.** A stop declared at the column the debugger advises pauses, and the refusal for a binding elsewhere on the line says where the stop is captured.

**A repository-browser run on the project's own port.**

- **The app runs where its origin points.** Codebook starts `next dev` on the port the project's `dev` script declares (its `-p`/`--port`, or a `PORT` it sets), never on another port, and opens it at `http://localhost:<port>`. `localhost`, `127.0.0.1` and `[::1]` at that port are one application origin, and Codebook holds `[::1]:<port>` for the run, so no other process answers there. The recorded browser resolves `localhost` as the system does, so the app's calls to your other local services reach them.
- **A busy port is refused, not moved.** Your own dev server on that port, an earlier Codebook run that is still stopping, a port the system does not permit and any other bind failure are each refused with the port and the recovery.
- **The `dev` script is read, never run.** Codebook reads a fixed set of forms and reads each script with the meaning of the shell that runs it (`sh`, `cmd` on Windows, Bun's shell, Yarn 2's portable shell). Any other form takes Next's default 3000, and the run resource's `applicationPortSource` says why and quotes the statement by its structure only, never a value. A `dev` script that runs more than 256 statements, and a `package.json` that is not a regular file or is larger than 1 MiB, are not read. The run resource reports `applicationOrigin` and `applicationPortSource`.
- **Server stops in every webpack layer.** A declared server stop is captured in whichever layer's copy of its module runs (`(action-browser)`, `(middleware)`, `(rsc)`), each placed by its own source map; the stop's snapshot serves that copy's own JavaScript and source map, which its hashes name.

**Compatibility.** The MCP API stays 1.8 and the bundled skill is unchanged; the run resource adds `applicationOrigin` and `applicationPortSource`. No stored format changes.

**Observed natively.** In VS Code 1.142.0 and Cursor 3.26.16 on macOS (the Space `local:codebook-qa`, OBS Window Capture, frames inspected): the recorded-source tab, its label and CodeLens and the moves between moments, frame by frame; the first Open replay after live runs (with Cursor's Agent too); Restore; Cursor's Learning summary container; the browser replay's frames; a sign-in through the project's own port and origin to the dashboard, with a server stop in Next's middleware layer. These ran on development candidates of this release's branch, not on its final commit: each observation's candidate commit, VSIX SHA-256, request and take SHA-256 are in [Issue #118](https://github.com/laststance/codebook/issues/118)'s N50 comments ([VS Code](https://github.com/laststance/codebook/issues/118#issuecomment-6372406316), [Cursor](https://github.com/laststance/codebook/issues/118#issuecomment-6372962294)) and rechecks ([F413 and F382](https://github.com/laststance/codebook/issues/118#issuecomment-6375221900), [F459, F474 and F485](https://github.com/laststance/codebook/issues/118#issuecomment-6378038329)). The recordings stay in private storage. Windows and Linux are not run.

## [0.2.37.0] - 2026-10-23 (development candidate)

Cycle 0050's second pull request ([Issue #118](https://github.com/laststance/codebook/issues/118)): a test replay's Application pane and Study section. The recorded-source tab and the moves between moments come with the third.

**The Application pane of a test replay.**

- **Your place in the output is kept.** The choice to follow the latest output and the line you read are kept per replay by Codebook, not by the page, so a rebuilt pane, a Retry, a presentation change or a page VS Code reloads opens where you were, with **Jump to latest** when you were reading higher up. Scrolling up stops following and Jump to latest follows again, decided by the scroll position alone. While you read higher up, a later moment that drops the earliest kept lines leaves the line you read where it stood.
- **Show recorded output brings a closed pane back above the source.** It opens in a group of its own above the recorded-source tab's group, and no other pane moves; when your editor kept the emptied group (`workbench.editor.closeEmptyGroups` off), the pane returns into it.
- **Opening another test replay** leaves the replay you see as it is until the other one shows, and the loading line names the replay being opened. A view the page did not take is sent again.
- **Output reads as the test printed it.** Color sequences and terminal strings that the recording split across two pieces are removed whole, an unterminated one removes only itself, and a recording full of them is cleaned in time linear in its length. Lines with emoji count each emoji once, and the muted lines read `1 earlier character not shown` and `1 Node inspector line hidden` in the singular.
- **Faster in long recordings.** Moments in a burst are drawn once per frame, newest only, unchanged lines keep their place on the page, and the output is read once per opened replay.

**The Study section of a test replay.**

- **No hidden reordering.** Bidirectional and terminal controls are removed from every text the section, the Application header, Saved studies and the learning summary print: test titles and files, output and result lines, stop paths, frames and values, and the learning material's question, title, summary, participants and steps.
- **Why a capture is partial or interrupted** shows under the status, on one line in test replay words.
- **Inspect in native debugger beside Show Variables.** While the debugger shows the stop and its values are not loaded, the row says `Debugger stop selected`; once the debugger no longer shows the stop (you ended its session, or it could not start), **Inspect in native debugger** there starts it again. The button follows the selected stop, also while the event list shows another page.
- **Quick moves add up.** Two quick Next presses move two stops, and a move that fails, or that a Close, a reopen, Return to Live or a browser recording cuts off, gives its place back, so the next move starts from the moment shown.
- **Keyboard.** A long title is a tab stop that shows whole on focus, the Application pane's output region is a tab stop you can scroll by keyboard, a control that leaves during Play hands the focus to the transport, and a control you reach with Tab never hides under the sticky transport.
- **The sequence diagram** wraps names and labels at word boundaries, also Japanese and Chinese text, and scrolls by keyboard to its last participant.
- **Test replay words.** Saved studies rows read `Test replay · …`, and refusals say test replay where they said Node history: `Test replays cannot be deleted here yet.`, `There is no next stop in this test replay.`, `The replay debugger was stopped. Select this stop or use Inspect in native debugger to restart it.` (said by a seek or Play that reaches a stop after you stopped the debugger; Next stop, Previous stop or Inspect start it again).
- **A browser recording opened while a test replay is selected** retires the test replay, and the Application pane shows the recording's own pages.

**Another window of the same workspace.** A test history that another live window records is listed and opened as recording, not interrupted, and its journal is read only where it grew; once that window seals it, it reads with its sealed status, and if that window ends without sealing it, as in a crash, it reads interrupted. A writer record that could not be read for a moment is judged again a few seconds later.

**Compatibility.** The MCP API stays 1.8. A history being recorded now carries a small writer record in its folder, removed when it seals; earlier versions ignore it, and test histories, learning materials and reader positions open in both directions unchanged.

**Observed natively.** Show recorded output after closing the pane, in VS Code 1.142.0 and Cursor 3.26.16 on macOS: the pane returns alone above the source and nothing else moves. ## [0.2.36.0] - 2026-10-23 (development candidate)

Cycle 0050 is a bug-fix cycle ([Issue #118](https://github.com/laststance/codebook/issues/118)): it fixes the defects Cycle 0049 left, in three pull requests merged in order. This version holds the first: the test run's start, stops and refusals, saving and storing test replays, causes that name no private path, the bundled skill and the tests that failed under load. The Application pane and the Study section come with the second, the recorded-source tab and the moves between moments with the third.

**Starting a test run.**

- **A full library is said before the start.** While saved studies and test histories take every place of the Saved Study Limit, `codebook_status` reads the `node-test` profile not ready and names the places taken and the limit. A start is refused with `PREREQUISITE_MISSING`, worded as the study library's own refusal: raise **Codebook: Saved Study Limit** in the Settings of this editor profile, or delete a saved study from Saved studies; only the learner can do either.
- **Checks before the history begins.** The cited files, the editors' open documents of the cited sources and the repository's root Vitest program are checked before a history begins, so a refused start leaves no empty test replay behind. A root `node_modules/vitest` that links outside the repository is named as such: Codebook does not run it.
- **Stops where the debugger binds them.** A declared stop that the debugger binds at another column of its line is accepted and captured where it binds. A refused stop position names the stop (`source` or `additionalStops[n]`), its `anchorIndex`, the cited path and lines, and which check failed, with what to send instead.

**During and after a test run.**

- **A stop before the first stop reads stopped**, not refused, and offers no `read-history`. After a stop whose release failed, the run offers only `stop`, and a continue is refused with `STALE_PAUSE`.
- **A seal that meets a passing failure is tried once more.** A history's seal that fails with `EMFILE`, `ENFILE`, `EBUSY`, `EAGAIN` or `EPERM` is retried once after 200 ms.
- **Empty and damaged histories.** A test history that ends with no entry is removed when it seals: it is listed nowhere and takes no place of the limit, and its run offers no `read-history`. A history that holds a saved learning material or understanding marks is kept, and so is one whose seal records entries but whose journal was lost: a status call or a list never removes it.

**Saving the learning.**

- **Save before the first stop does nothing** and says `Nothing to save yet: the test run has not reached its first stop.`, and the run goes on.
- **The agent's claim of saved learning** also needs `nodeTest.captureMissing` empty (bundled skill 1.0.47). The run resource and the `codebook://node-history` resource list the capture gaps; when the seal could not read them for a passing reason, the next learning-material save reads them again.
- **A replay debugger that cannot start** (a declined workspace trust, the capture timeout) no longer fails the open: the replay opens on its moment, the Study pane says `The replay debugger could not start: <cause>. Select this stop or use Inspect in native debugger to restart it.`, and Retry starts it again. A debugger you stopped stays stopped when you move to an output or the result.
- **`codebook_playback` refuses a test replay** with `PLAYBACK_PROFILE_UNSUPPORTED`, also one of an earlier session that this window has not listed yet.

**Causes name no private path.** Every cause an agent or a learner reads (MCP answers and refusals, the run resource, `codebook_status`, Saved studies, the book catalog, notices, Output › Codebook) shows the extension's storage folder as `<storage>`, the opened repository as `<workspace>` and the home directory as `~`, also under their real paths. A long cause that a tooltip, a notification, the run resource or an MCP message shows is cut between characters and ends with `… [cut]` (the run resource shows at most 300 characters of it); the Output › Codebook entry keeps the whole cause.

**The bundled skill (1.0.47).** In a new VS Code chat that runs in the Copilot harness, where Codebook's MCP tools are not reachable, the skill tells the learner to open a Local chat session, as **Codebook: Set Up AI Chat** says.

**Compatibility.** The MCP API stays 1.8. No stored format changes: test histories, learning materials and reader positions written by 0.2.35.0 open unchanged, and those written now open in 0.2.35.0. A history sealed with no entry by an earlier version is removed when a list or a count meets it, unless it holds learning material or understanding marks.

**Not observed.** No native run of this version yet; the native checks of this cycle run with its second and third pull requests. Windows and Linux are not run.

## [0.2.33.0] - 2026-10-22 (development candidate)

Cycle 0049 is a feature cycle ([Issue #107](https://github.com/laststance/codebook/issues/107)): a Vitest test run that the editor chat explained becomes a learning replay, a **test replay**. It is delivered in three pull requests, merged in order; this version holds the first, the loop and its contracts. The recorded test output in the Application pane and the summary's selected step come with the second, the recorded source with its transitions and the native round in both editors with the third.

**A test run becomes a test replay.**

- **Ask about a test.** Ask `/codebook` in Copilot Chat or Cursor Agent about a test, or about library behavior a test exercises. The chat starts a `node-test` run of that test with the Vitest at the repository root, pauses at the stops it declared, explains each from its captured values in the chat and continues to the result.
- **Save learning replay.** While the run records, the status bar reads `Recording explanation · stop <n> of <m> · Save learning replay` (once its checks have passed and until its first stop, `Preparing the test run…`). Saving before the result asks first, because it ends the run. Save seals the test history and reads the chat's learning material: `Learning saved · Open replay` when the test passed, every stop's recorded debugger state verifies and the material explains every stop and the result; otherwise `Learning partially saved · Open replay`, whose tooltip names the result and what is missing and whose notification says what to ask the chat for, or that only a new run records it. A failing test's replay is saved too. A failed save says which stage failed (stopping the run, sealing the history, reading it back) and what its button does.
- **Open replay.** Open replay, and a test replay's row in Saved studies, open it in the Study pane at its saved reader position, or on its first stop whose recorded source verifies: its test output, the executed source and the native debugger's recorded values and stack at each stop; no application video. During a browser replay Codebook says that one replay shows at a time, with **Close browser replay**.
- **Saved studies** name each test replay's result, capture and explained stops, for example `Test replay · Test passed · exit code 0 · capture complete · 2 of 2 stops explained`. The sentences that called a test history's replay or application video unavailable are gone; until the second pull request the Application pane says that the recorded output is in the Study pane.
- **Output › Codebook.** An unexpected failure on these paths writes one entry with the surface, the study, the profile, the versions, the cause and the stack. The causes these new paths show (the Save item's tooltips and notifications, the Output entry, a test history's seal failure and `HISTORY_SEAL_FAILED`) name the extension's storage, the workspace and the home folder as `<storage>`, `<workspace>` and `~`; some other messages can still show full local paths.

**For the agent (MCP API 1.8).** A node-test run reads `demonstrated` in `finalOutcome` once its test passed after every declared stop, and in `studyOutcome` and `recordedStudyOutcome` once its history sealed complete; before, it read `partial` at most. Its run resource adds `nodeTest.testResult` (`passed`, `failed`, `signal` or `none`), `nodeTest.learningCoverage` (`complete`, `partial` or `none`) and `nodeTest.learningMissing`, and `nextActions` lists `save-node-learning` until the coverage is complete; the node-history resource reports the same three fields. A node-test start's checks (a changed stop source, a changed test file, a path that is not a file, a root Vitest missing or older than 4) run during preparation and end the run with a typed `error` before its first stop, which records no history and frees the run's slot and key; `codebook_status` names a missing or older root Vitest before any start. `codebook_stop` answers `HISTORY_SEAL_FAILED` when it could not seal the history of the run it ended, `codebook_playback` refuses a test replay with `PLAYBACK_PROFILE_UNSUPPORTED`, and `codebook_explain_node_history` refuses a step that cites another event than it claims with `INVALID_REFERENCE`, naming what that event is. The node-test help gains a complete example, the ordered walkthrough of the calls and the root-Vitest limit. A test that ends with a non-zero exit code or a signal keeps that result even without Vitest's report, and a passing run whose first release failed seals complete once a retried Stop releases it.
