## First-use contract

One action in the intended trusted work window, **Codebook: Set Up AI Chat**, prepares the skill and a private current-instance MCP connection. Then the learner selects `/codebook` in a new standard chat. The AI must ask `codebook_status` first and continue from public state/help; ordinary code prose is not counted as Codebook execution. A restarted window rotates instance credentials and re-registers only for the same recorded workspace. A missing skill, missing host API, changed workspace or failed server setup has a visible recovery instruction, not a success notification.

| Host | Chosen primary mechanism | What the mechanism alone cannot prove |
| --- | --- | --- |
| VS Code | Package `skills/codebook/SKILL.md`, declare `contributes.chatSkills` pointing at that file; after explicit setup advertise a window-local `McpHttpServerDefinition` and refresh its descriptor on resolve. | Copilot Chat actually discovering the skill, choosing the intended body and issuing the right MCP calls. |
| Cursor | From the same package bytes, install only a receipted user skill at `~/.cursor/skills/codebook/SKILL.md`; register a local stdio bridge through `vscode.cursor.mcp.registerServer` with a unique instance name. The child reads this window's private descriptor and forwards to its authenticated HTTP MCP server. | Agent discovery/precedence, slash visibility, MCP tool availability and restart behavior in the targeted ordinary version. The extension API is for MCP registration, not the unproven plugin-skill alternative. |

The [VS Code contribution reference](https://code.visualstudio.com/api/references/contribution-points) names a relative `SKILL.md` path. The [VS Code MCP provider guide](https://code.visualstudio.com/api/extension-guides/ai/mcp) documents provider contribution plus dynamic HTTP definition; installed Copilot behavior still needs observation. ## Ownership and failure review

Cursor's user skill is shared across windows. The private receipt records the deployed path, skill/extension version, SHA-256 and file identity. Setup refuses an unowned directory, edited or replaced file and redirected path; a managed update keeps the previous owned body privately. Ownership checks require the original inode and exact SHA-256 at that path; the receipt's device number is retained for same-filesystem transaction placement but is not used to reject the same file after a macOS volume device-number change. A staged-file journal records the exact inode before publication, so an interrupted installation or update is either rolled back to the verified previous body or completed only from the recorded new inode and bytes. Updating/removing first displaces the exact old file, then moves the actual displaced body into retention on the same filesystem instead of unlinking after a prior ownership check; a conflicting learner file remains available with its recovery record. Explicit removal and restore remain user commands. A lock in extension storage serializes simultaneous Codebook writers. It is never automatically displaced because two recovery attempts could race a live writer; an interrupted lock requires explicit resolution after all affected windows close. This does not establish the host's loaded skill precedence; native inspection must compare the resolved body/version with the VSIX and detect another same-name skill.

The MCP server remains per window with an instance-specific token and loopback URL; neither appears in the skill body, VSIX content or public evidence. A workspace identity stored after setup gates automatic reconnect and provider discovery. A different repository requires setup again. Cursor registration uses an instance-unique name to avoid replacing another window's server. The first direct HTTP registration failed in Cursor 3.21.16 because it omitted configured headers, so [D024](../../DECISIONS.md#d024--bridge-cursor-mcp-over-local-stdio-on-the-target-version-2026-09-23) selected the private stdio bridge. A later development cut woke Cursor's dynamic MCP catalog by changing only the modification time of an existing user `~/.cursor/mcp.json`, preserving its bytes, or creating a private empty file if none exists. Current source receipts the identity and hash only when Codebook creates that empty file. Explicit managed-skill removal retires only the exact unchanged owned config into private storage; pre-existing, edited, replaced, redirected and unreceipted legacy files remain. Setup resolves an interrupted retirement before recreating a missing file. Setup never inserts a static Codebook server or credential in that file, and never edits a repository MCP config. Focused filesystem and command-boundary checks pass; ordinary installed cleanup/restore, full application restart and exact final-candidate proof remain open.

| Production failure | Current control | Evidence still needed |
| --- | --- | --- |
| Same-name or later-edited Cursor skill | Refuse write/removal; hash plus file identity and private receipt | Normal-profile precedence and conflict UI |
| Interrupted skill update | Private transaction journal and prior-body receipt enable exact-inode recovery; mismatched edits cause refusal | Normal-profile recovery and visible guidance beyond filesystem regressions |
| Dead token after editor restart | New server/descriptor, provider refresh or Cursor re-registration; exact expired-session 404 reinitializes the bridge | Actual chat `codebook_status` after normal restart and 5-minute idle |
| Wrong workspace/window | Stored workspace comparison and per-instance server names | Two concurrent dedicated windows and negative cross-instance trial |
| Skill appears but AI ignores MCP | Thin status-first instruction, real chat observation | Tool-call/result transcript, source/value cross-check and truthful negative answer |
| Cursor API is missing or registration is invisible | Setup raises a clear error; the target-version stdio bridge passed one reload trial | Full process restart and exact final-candidate check; revise route before G12 PASS if it fails |

## Check scope

Focused checks cover package inclusion, manifest contribution/reference, first install, repeat, update, same-name collision, post-install edit/replacement, removal/restore and per-host registration/credential rotation. Full product and package suites guard the existing execution path. Native installed checks must use the same VSIX sequentially in dedicated VS Code and Cursor windows, record extension/host/chat/model/skill identity, actual AI calls and inspected screen video. This is one sequential integration path; parallel implementation or screen operation would obscure ownership and evidence. Neither automated contracts nor a successful existing external MCP client satisfy G12.
