The version record must travel with the VSIX and remain inspectable after Cursor deployment. Record the complete `SKILL.md` hash, canonical source path, packaged path, deployed/resolved path and originating release/build; a slash label or equal extension version alone does not prove loaded content. Identify same-name overrides and host precedence rather than assuming the intended copy won discovery.

Do not infer file ownership from its name or matching bytes alone. Setup must detect collisions before writes, retain recoverable previous owned content and avoid partial updates. Recheck ownership and current content before update/removal/restoration; a user edit or another installation's update must not be overwritten. User-level deployment is shared across windows: account for concurrent setup and different installed extension versions without silently replacing a skill used by another window. Keep ownership receipts and backups separate from the common instructional body. Exact storage/transaction details belong to the selected implementation cycle.

Future skill updates select the requested feature: live explanation uses real opened projects/native debugging; learning saves synchronized execution history; Wiki generation/update follows the [DeepWiki generation-skill contract](deepwiki-generation-skill.md), without runtime/debug MCP or learning material. Wiki requests must not be forced through live Study entry or a failed runtime status check. Retire demo/theme/custom-values instructions with implementation, preserving truthful capability discovery. This document change alone does not alter the bundled skill.

The thin body routes by feature first. Live/replay begins with `codebook_status`, follows public help/current state and obtains current-run continuation arguments. DeepWiki delegates to the shared generation guidance through ordinary editor-agent workspace capabilities, without a runtime/debug-MCP prerequisite. Both routes distinguish observations, source reasoning and unknowns. It connects to existing features, including recording/replay, without reproducing their detailed schemas. It never completes learner understanding or inserts correct repository breakpoints/values. On the live/replay path, if status itself is unavailable, it explains the missing connection/prerequisite and the published recovery path; it does not claim runtime success from a source-only answer.

## Validation before the final campaign

1. Complete focused packaging, lifecycle/conflict, connection/restart and negative controls. Include a pre-existing same-name skill and a later manual edit without altering real user content to manufacture the test. Publish exact setup, update, remove, restore and recovery instructions only when implemented.
2. Build one identified VSIX and normally install it in each required editor. Use dedicated windows and authorized logged-in profiles, preserving work/settings/skills and recording reversible changes. Record host/chat/model and skill identity. Development hosts and direct source loading cannot validate this distribution path.
3. For runtime/replay in each actual chat, discover `/codebook`, submit the same natural question and separately observe context loading, the AI's first `codebook_status` and subsequent Codebook calls/results. Repeat after normal restart; exercise disconnected/unavailable conditions through public controls. Read-only verification cannot perform a missing workflow on the AI's behalf. Preserve video and inspect frames for visible operation and correspondence.
4. Keep all prior capability gaps open. Follow [D029 two-stage acceptance](../acceptance/FINAL_REVIEW.md): the main agent first passes all nine mandatory projects in both hosts; then nine independent project-specific junior reviewers evaluate both hosts. Freeze body/version/hash, registration/setup and guide with the VSIX. Changes require evidence impact assessment and affected regression trials, not a consecutive-pass reset.

Development QA and code review never count as either acceptance stage. Skill discovery alone, a generic explanation, direct reviewer MCP substitution, a timeout or an unverifiable loaded identity cannot pass the final protocol. Test understanding is not owner acceptance. Claude Code CLI long reviews remain skipped.

## Additional routes and research limits

A Cursor plugin-registration route is conditional: first demonstrate skill discovery, `/codebook` visibility and actual invocation in an ordinary installed target version. An API name or source declaration alone cannot qualify it. The user-directory route remains the default.

MCP Skills Extension / SEP-2640 may later distribute the same skill as an additional transport. Acquisition, host recognition/activation and slash availability through that route have not been verified across both required editors. Do not wait for it to complete the product. ### Initial integration reconnaissance (2026-09-23)

The following was a pre-implementation snapshot, not a statement of current support:

- At that checkpoint, [extension activation](../../extension/src/extension.ts) created a private connection descriptor for each running workspace instance, removed it on stop, and copied a token-bearing MCP configuration through `codebook.copyAgentConnection`. Neither the manifest nor activation then registered a chat skill or MCP provider. Preserve instance/workspace identity and private credentials when replacing this manual onboarding path; a shared skill file cannot carry them.
- [VS Code Agent Skills](https://code.visualstudio.com/docs/agent-customization/agent-skills#contribute-skills-from-extensions) documents `contributes.chatSkills`, a `codebook/SKILL.md` folder whose name matches frontmatter, and explicit slash invocation. The page currently conflicts with itself about whether the contribution `path` names the containing directory or the `SKILL.md` file; its JSON example names the file. Resolve this in the normally installed target host before treating discovery as verified.
- The [VS Code MCP extension guide](https://code.visualstudio.com/api/extension-guides/ai/mcp#register-an-mcp-server-in-your-extension) documents `contributes.mcpServerDefinitionProviders` plus `vscode.lm.registerMcpServerDefinitionProvider`, including an HTTP definition and resolution when a connection is needed. Evaluate this as a window-local connection candidate against real Copilot Chat behavior, restart, workspace changes and unavailable states; the documentation alone does not establish Codebook compatibility.
- [Cursor Agent Skills](https://cursor.com/docs/skills) documents `~/.cursor/skills/codebook/SKILL.md` and `/codebook`, but also discovers other project/user skill directories. Test same-name precedence and the actual loaded file before claiming the deployed copy won. [Cursor MCP documentation](https://cursor.com/docs/mcp) describes project/global `mcp.json`, interpolation and a programmatic registration API; assess each connection route in the installed target version for correct window/workspace binding and reconnection. A global static endpoint or copied token is not sufficient evidence of those properties.

Recheck the target versions and official contracts when implementing. The options above are not implementation, normal-install validation, proof of a plugin route, or proof of MCP-distributed host compatibility.
