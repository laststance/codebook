## Question and authorized scope

Does one natural `/codebook` request, declared by the editor's own agent from source alone, pass on its first admitted run in Copilot Chat and in Cursor Agent on the delivered source, and can the learner save it and reopen it as a learning replay? If not, what stops it, and does it pass once that is fixed?

Why now: it is the product's defining experience (PRODUCT_GOAL, "Defining live-to-learning experience"; AC-LIVE, AC-SAVE). The same frozen request has been measured since Cycle 0036 and has never passed on its first admitted run in either chat. Cycle 0044 changed the live-run code the most (object inspections, the anchor index refusal, a stop on a line without a mapped position, the binding and pause rules) without one chat run (its row T-5). Every later step of the route, the nine-project Stage 1, starts with this request shape.

- Hypothesis: with the causes of Cycles 0041 to 0043 fixed in 0.2.28.0, the frozen request reaches its observed result on its first admitted run in at least one host; what still stops it is a small number of Codebook rules or texts, each fixable with a test.
- Smallest observable outcome: Issue #85 Part 1, acceptance criteria 1 to 9.
- In scope: Part 1 (the increment) and Part 2 ([the 222 carried rows](0045-carried-defects.md)).
- Out of scope for this cycle (still retained in PRODUCT_GOAL.md): another natural question, another target repository, the nine-project matrix and final acceptance; Node test and library runtimes; repository-specific guidance in the skill or the help.
- Conditions that falsify the approach: a first admitted run that fails for a reason no bounded fix removes (for example a debugger behavior Codebook cannot observe), or a request that passes only after the agent read material of a run it did not start.
