## Provisional adapter boundary used for screening

The current `repository-browser` adapter requires a trusted local Git repository with installed dependencies, Next.js 16 started by `next dev --webpack`, the default `.next/dev` output, a direct `/` App Router route with its `/page` client manifest, retained original source maps, and a uniquely visible enabled element for one click. It accepts one source-bound browser pause with actual primitive value inspection. It does not launch arbitrary commands, ports, roots or non-root routes. The final support declaration and any eligible random pool must be fixed before the acceptance draw; these screening observations do not fix either one.

## Product finding and repair boundary

The 8 MiB limit conflated a webpack chunk containing many modules with Codebook's selected module. A real root chunk exceeded 8 MiB while the exact selected module was only 36,577 bytes. The source now reads at most 32 MiB per declared chunk and retains the existing 128 MiB total, 2,048-candidate and 30-second discovery guards. It still accepts at most 8 MiB for the selected JavaScript module, 16 MiB for its inline map and 256 KiB for the original source. The eval-payload scanner is iterative so an oversized quoted module cannot overflow recursive regexp matching before the module limit check. It decodes the two observed webpack literal forms as JSON and never executes application code.

Focused extension tests cover large-chunk/small-module discovery, selected-module oversize, chunk oversize, unchanged-source identity and repository runtime/profile contracts. The executable source cut passed **898/898 extension** and **100/100 package** checks, plus `git diff --check`. A documentation-only JSDoc edit followed those tests; it changed no executable code. Direct `createBundleVerifier` construction on the dashboard's selected source, emitted module and map passed after the server stopped. The dirty development VSIX at `artifacts/cycle-0019/codebook-0.2.3-large-chunk-preflight.vsix` is 907,003 bytes, SHA-256 `e8f88e586eae4858cfce40190188aa7871b9806a74d0d8ef1a115a8e96679604`, source hash `50c4783f57f1425c1cb447428d6ae76af729374abba77177b176c193d7629b26`, and packages the unchanged skill SHA-256 `4ba173b890b94bbc31cb7e603925c8a5ab79cdb9c991fc02e45d6a692d4d7d0f`.
