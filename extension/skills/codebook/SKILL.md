# Codebook

Use this skill for the user's request in the current editor workspace. Begin with `codebook_status` to confirm the workspace, instance, available capabilities and prerequisites. If the Codebook tools are missing or the connection is unavailable, say what is missing and direct the user to **Codebook: Set Up AI Chat** in this editor. Do not claim an observed result from a generic source explanation.

`codebook_status.build.dirty` describes the packaged Codebook extension source, not the target repository. Do not claim the workspace has uncommitted changes unless its Git state was checked separately.

Follow the public Codebook help/resources and the returned current state to select only the tools needed for the request. If this chat cannot open a returned MCP resource URI, use `codebook_read_resource` with that exact URI. When relevant, inspect source, operate the application, pause execution, read actual values, explain the relationship, continue from the **current** run state using its returned arguments, and save or replay a recording. Do not invent stop locations, values or repository-specific steps.

For a request requiring runtime observation, open the learner presentation before the first application input. Read current presentation state and use `codebook_presentation` to select its reported mode when closed; this preserves a saved Living book or Guided walkthrough preference and uses Study for the normal default. Follow the public tool contract for current identity/revision arguments. Confirm an open presentation and `layoutConfirmed: true` before proceeding. If the mode, preference or layout cannot be confirmed, follow the returned recovery guidance and report the unresolved condition; do not silently replace an unknown preference or claim a visible workspace.

For a request requiring runtime observation, read the selected profile's public help and verify that the source and visible control belong to its launched route. Build the action selector from an attribute or structure verified in that source or the rendered DOM; treat presumed library defaults as unverified. Choose a mapped source statement reached by the action or a resulting state-driven render, then use Codebook's managed run before launching a separate development server or browser; an independent server can take the app's build lock and prevent Codebook from controlling execution. Poll the returned run resource for readiness or the actual failure cause, and follow its source and run prerequisites. If a pre-click selector check fails, inspect its cause and the control markup before a new run. If the source chunk is missing or a stop cannot bind, read the reported failure and check the route and another executable location before concluding that runtime observation requires application edits. An exact-binding timeout may list positions from the frozen source map. Those positions are mapping hints only; inspect the cited source and choose a statement the action can reach. When a library owns the click callback, choose an executable statement in the component's resulting render, such as an enclosing JSX element opening or a function-body declaration that runs again after the state change. After a JSX property fails to bind, move to one of those statements and widen the cited source if needed; adjacent property positions test the same weak hypothesis. Use the exact listed column when trying a mapped position, and require a real bound pause before claiming any value.

For each committed pause in a runtime explanation request, read its snapshot and source, then save the grounded explanation with `codebook_explain` using the public tool contract. Wait for the committed explanation receipt before continuing. Writing an explanation in chat does not save it to Study or recording. When the request concerns visible behavior, read the returned phase image resources and describe their actual pixels; capture metadata alone is not an image inspection. Preserve observed facts, source-based interpretation and unknowns as separate claims.

Before starting a new run with an open presentation, read `presentation.reader.followingCurrentRun` and `presentation.reader.contentTab`. If following is `false` or the content tab is not `live`, use `codebook_return_current` with the current reader revision. Verify both `followingCurrentRun: true` and `contentTab: live` before starting, so pauses show captured values and saved explanations instead of the source-only Overview. This only changes the selected view; do not repeat an application action to recover the reader.

While a Codebook run is preparing or active, poll that run's returned state until it becomes ready or terminal, or reaches its published preparation deadline. During repository preparation, use `preparationRemainingMs` from the **current** run resource: a positive value means the deadline has not expired, regardless of local time-zone display. An unchanged preparing state is normal while the app loads; do not stop it early unless the user cancels. Do not kill processes or remove build locks to assist it; use Codebook's stop operation for owned resources. If a foreign lock remains after no Codebook run is active, report the condition instead of stopping another process on the user's behalf.

After stopping a run, read its current run resource until history and recording receipts settle. Claim a saved study only when `studyOutcome` is `demonstrated`, and claim a replayable recording only when `recordedStudyOutcome` is `demonstrated`; `finalOutcome` alone describes runtime evidence, not durable storage. Before claiming replay of explanations, follow the recording's returned `contextUri` and verify that each observed pause retains its interpretation. Report any missing interpretation, storage limit or failed receipt even if the click, pause and screen checks succeeded.

When linking an observed moment in a later article revision, copy `studyId` from that run's resource and `observationId` from its `observations[].id`. The runtime session ID inside a pause or artifact path is a different identity and cannot locate the saved Study archive. Publish the link only after the run's saved history is confirmed; retry a failed publication with a new key only after correcting its input.

Separate directly observed facts, source-based inferences and unverified points in the answer. Use connection identifiers only in tool arguments; do not repeat credentials, endpoints or temporary instance IDs in chat prose. If a prerequisite or capability is unavailable, explain the limit and the next normal setup step. The learner alone decides whether an understanding check is complete; never mark one on their behalf.
