For a local build, follow the next section; the package command reports the VSIX SHA-256 in its JSON receipt and does not create `SHA256SUMS`. Verify downloaded workflow bytes in their directory:

```sh
shasum -a 256 -c SHA256SUMS
code --install-extension /absolute/path/codebook.vsix --force
cursor --install-extension /absolute/path/codebook.vsix --force
```

This checksum identifies the exact downloaded VSIX and detects changed bytes; it does not authenticate the publisher. Obtain both files from the trusted private workflow. ## Build and verify a package

Package builds require a POSIX host (macOS or Linux); Windows builds are rejected before launching tools because the cleanup contract uses owned process groups. Maintainers use **Node 24.21.0** and the integrity-pinned **pnpm 12.4.2** in `package.json`. Installed-editor support remains the separately validated macOS matrix above. From the repository root:

```sh
pnpm --dir experiments/cycle-0001 install --frozen-lockfile
pnpm --dir experiments/cycle-0004 install --frozen-lockfile
pnpm --dir extension install --frozen-lockfile
pnpm --dir extension package
pnpm --dir extension package:check "$PWD/artifacts/packages/codebook-0.2.2.vsix"
```

The package command checks that pnpm starts before removing only the three packages' known compiler outputs, then rebuilds, bundles the extension, copies the ten original demo source/JavaScript/map/HTML files and includes manifest icons and dependency licenses. It rejects source changes during the build, unexpected imports, missing assets and invalid archives before replacing the requested VSIX. Use `pnpm --dir extension package --out /absolute/path/codebook.vsix` for a different destination outside source/build directories, including case variants of owned directory names. A failed build or final rename preserves an existing VSIX. Do not run packaging concurrently with another build in the same checkout.

The VSIX includes `package-manifest.json` with file hashes, captured dependency/input identity, the running Node/pnpm/esbuild versions and the resolved extension TypeScript/vsce package versions, plus `dist/build.json` with source revision, dirty state and source hashes. `THIRD_PARTY_NOTICES.md` links the bundled dependency licenses. The separate check command verifies archive structure and metadata without executing supplied extension code; its self-consistency checks are not a publisher signature. The build additionally loads its own verified artifact in an unrelated temporary directory without repository dependencies. Normal installed activation and native workflow evidence are separate checks.

Archive checking and the reported SHA-256 use the same captured bytes. The checker rejects archives larger than 64 MiB, more than 2,048 entries, or more than 64 MiB of declared expanded content. Each package subprocess has a three-minute timeout and an 8 MiB limit for each output channel. The runner terminates its owned process group and waits up to five additional seconds for cleanup before returning. A failure to confirm cleanup rejects the build; combined failures retain the original error code/signal alongside the cleanup error. Failures preserve the previous VSIX. SIGINT/SIGTERM/SIGHUP/SIGQUIT during a package command reject with an interruption error after retiring its group, allowing the caller to remove its stage before the CLI exits nonzero. Existing caller signal handlers remain installed. Signal ownership ends when that command and its cleanup settle. A first or later signal during outer bundling, staging, verification or publication can terminate the process and leave scratch; transaction-wide cancellation is not promised. SIGKILL, immediate termination by a caller handler and independently detached descendants are outside this cleanup contract. Duplicate dependency-notice paths are rejected before their content is hashed again.

Local builds can record a dirty source tree; CI and accepted validation candidates require clean provenance. Clean means every selected source, fixture, script, patch and listed package/configuration input matches the raw bytes stored by its recorded Git revision. Ignored additions, index-hidden edits/deletions and clean/smudge transformations that change selected bytes remain dirty even if `git status` appears clean. Ambient `GIT_*` overrides and replacement refs cannot redefine that identity; provenance reads disable Git's optional index writes. Clean source identity does not attest that pre-existing `node_modules` or tool binaries match the lockfile and patch bytes. Run the frozen installs above before building an accepted candidate; CI repeats those installs and the package records the dependency bytes actually bundled. The inventory/checker accepts SHA-1 and SHA-256 Git revision formats; this does not establish a full build or native installation from a SHA-256 repository.

The private VSIX intentionally includes relative source/test paths and hashes in its build metadata. Those inventories are visible to anyone receiving the archive. Review or minimize that metadata before any public Marketplace/Open VSX distribution.

CI runs the product/runtime tests and real packaging/failure tests before uploading only the VSIX, build receipt, verification receipt and checksum, with clean provenance required. Native recordings and connection descriptors stay outside distribution. Workflow artifacts expire after 14 days; preserve any artifact needed for later acceptance together with its checksum in the private evidence store. For local regression testing, also run `pnpm --dir experiments/cycle-0010 install --frozen-lockfile`, build Cycle 0010 and the extension, run the compiled suites, then run `pnpm --dir extension test:package`; package tests run sequentially because the integration test cleans shared compiler outputs.

## Shared presentations (API 1.5)

Choose **Codebook: Select Presentation** or use the **Presentation** selector in the explanation pane. Study workspace places application above source beside the explanation; Living book gives reading the larger left pane; Guided walkthrough places application and source side by side above the explanation. Overview, Live and Recording remain independent content tabs. The same learner selection, understanding and runtime remain in place.

| Mode | Intended use | Native arrangement |
| --- | --- | --- |
| `study-workspace` | Connect the application to the inspected code | Application above source; explanation beside both |
| `living-book` | Read explanations and their source references | Larger reading pane on the left; application and source on the right |
| `guided-walkthrough` | Follow an operation and its code | Application and source side by side; explanation below |

Agents discover `presentation` with `codebook_status`, then read its current-instance `uri`. Call `codebook_presentation` with the returned `instanceId`, `presentationId`, `presentationControlRevision` as `expectedRevision`, and `mode` (`study-workspace`, `living-book`, or `guided-walkthrough`). The optional `action` defaults to `select`; `restore` reapplies the selected layout, while `save-preference` retries saving the current confirmed mode without moving editors. Reading the resource never opens a reader, changes focus or starts execution. If a separate chat/floating editor part prevents a main-layout measurement, that read reports `layoutConfirmed: false` with a focus instruction; it preserves the stored mode/receipt. Focus a Codebook pane or text editor in the main window and read again. Same-mode selection also refuses an unverifiable scope without changing the saved preference or control revision.

A transfer pauses recording playback at its last fully displayed position. Confirmed transfers retain the source reading position for that same captured observation, including manually scrolled code away from the selected stop. A document edited during the transfer invalidates its captured pose: the transfer rejects explicitly and preserves the edited text. Native layout changes can briefly reveal the selected stop before restoring that position. Read the returned playback revision before the next Play/Pause/Seek. Pending application input, capture, continuation or navigation rejects placement before native effects. A stale presentation revision requires a fresh read; Close retires its reader identity immediately, independently from the agent server. After response loss, inspect applied mode, `layoutConfirmed` and the independent preference result before acting again.

The preferred mode is saved per workspace. A failed save leaves the successfully applied layout available and shows **Save preference**. Unknown preferences remain untouched until an explicit replacement. Foreign preview tabs and unsupported focused editors are preserved; keep a preview or focus a Codebook/text pane explicitly before retrying. Placement refuses an unowned main grid with more than three groups; manually consolidate only groups you intend to change. Separate chat/floating parts are not Codebook layout destinations. Cycle 0018 measures the main grid separately and preserves other parts; the earlier package's [cold-restart failure](#install-the-private-vsix) remains tied to its original archive. Use **Enlarge explanation** at constrained sizes and **Restore layout** to return to the selected presentation. At 200%, hide sidebars or the bottom panel if the requested native proportions do not fit. An unachievable layout remains unconfirmed and preserves the current evidence. Cycle 0014 passes 15 development theme/zoom cells per host; Cycles 0016 and 0018 add bounded ordinary installed mode/reading/restart checks. Full installed UX and uncropped 200% motion remain separate requirements.

Native-scope recovery can use an already validated Wiki article's actual retained citation to identify the main editor part before reserving its reading panes. It never inserts a temporary document as a substitute. An ambiguous empty library without a selected citation requires explicit main text-editor focus; a refused cold Wiki command shows an error. V29 separately verifies ordinary-installed positive and preserving-refusal behavior. ## Learn this repository

Run **Codebook: Open Repository Wiki** and connect your external MCP agent. Ask it to explain the selected repository with cited articles and relationships. Source-only authoring requires a trusted local workspace at its Git working-tree root; it does not require Chrome, a debugger or a runtime adapter for that repository.

1. Read `codebook_status.repository` and `codebook://help/repository`. Call `codebook_sources` with the current `instanceId` and follow `nextCursor`. A changed tracked-file set requires fresh discovery.
2. Call `codebook_source` for eligible tracked paths. Each result contains exact UTF-8 text, a full-byte SHA-256 and a line count. Citations use that path/hash and inclusive `startLine`/`endLine`; they are checked again before publication.
3. Author a complete plain-text document: a title, summary, uniquely identified article nodes with sections and citations, and relationships between existing nodes. Relationships describe source interpretation. They do not establish observed runtime order.
4. Call `codebook_publish_book` with a stable `bookId`, intent `key`, `expectedRevision: 0` for the first version, and the document. Later complete revisions use the current revision as `expectedRevision`. Reuse the identical key and input after response loss: the original immutable receipt remains recoverable after source changes. A different payload under that key is a conflict.
5. Read the returned book URI, then explicitly call `codebook_open_book` with its exact book/revision/node and optional citation index. Publication does not navigate or mark understanding. The reader opens the retained source in a read-only native editor and keeps the article beside it. **Open verified current file** is a separate action and requires matching current bytes.

Articles provide continuous prose, a contents menu, citation controls and source-derived relationships. Below 800 CSS pixels, the article occupies one column and relationships follow it. A newer publication offers **Load latest** while preserving the version being read. Selecting another article or citation opens that exact retained context; reopening restores its book, revision, article, citation, reading section and focus. Missing retained revisions are errors, with an explicit retry path.

The lowercase **understand** checkbox records only the learner's explicit decision. Its identity includes every unique citation's path, full hash and inclusive line range. Reordering or repeating identical citations, or changing only prose, retains the decision. Changing a secondary citation or range requires a new understanding decision. Current-file drift shows **Review needed** while retaining the earlier decision and captured source. Reading, publishing, execution and agent explanations never mark understanding.

Optional observation links must identify an exact saved study, observation and source hash. The store binds and verifies the saved facts; a runtime `learningItemId` alias additionally requires a matching linked observation for the article's primary source. Omit that alias for articles without runtime evidence. An existing article keeps its original learning identity across revisions; adding later observations does not require changing that identity. **View observation** opens saved evidence; **View recording** seeks its verified recorded time while paused. A missing recording disables only its recording link. **Return to Wiki** restores the retained article and reading position without rerunning the application. Partial studies stay labeled partial; source-only articles do not imply runtime support for the repository.

Evidence navigation preserves hidden outline/timeline panes so the article remains readable in a constrained window or at 200% zoom. Explicit **Open Study Workspace** still reveals those panes. Returning to Wiki switches a layout only while Codebook still owns it; manual group moves, sizes and zoom-induced changes are preserved. Use **Arrange Study Workspace** for an explicit reset.

Source discovery excludes hidden paths, dependency/build directories, lockfiles, secret/key filenames, symlinks and unsupported extensions. It is not a secret-content detector. Reads are bounded to regular tracked UTF-8 files: 5,000 tracked names, 100 names per page, 256 KiB per source and 32 sources per revision. Publication accepts at most 1 MiB of document JSON, 64 articles, 128 relationships, 12 sections per article and 8 citations/observation links per article. Retention is bounded to 16 books, 20 revisions per book, 4 MiB per revision and 8 MiB per book, without automatic eviction. Capacity, corruption, changed source and concurrent-revision failures preserve existing data.

The repository's [typed SDK client](https://github.com/laststance/codebook/blob/main/extension/src/client.ts) is a development helper; its separate modules and the examples are not shipped in the VSIX. Ordinary installed clients use the copied MCP connection. This source-reading example requires this source checkout and uses the private connection descriptor produced by a native session, not the copied MCP configuration wrapper. Run from `extension/` after building, with `CODEBOOK_CONNECTION` set to that descriptor's path and `CODEBOOK_SOURCE` to an eligible path such as `extension/src/service.ts`. It prints only the requested source and its identity; use the discovered authoring schemas and steps above to write the explanation after reading it.

```sh
node --input-type=module <<'NODE'
import { readFile } from 'node:fs/promises';
import { z } from 'zod';
import { StudyClient, connectionSchema } from './dist/client.js';
import { repositorySourceSchema } from './dist/repositorySchemas.js';

const connectionPath = process.env.CODEBOOK_CONNECTION;
const sourcePath = process.env.CODEBOOK_SOURCE;
if (!connectionPath || !sourcePath) throw new Error('Set CODEBOOK_CONNECTION and CODEBOOK_SOURCE.');
const connection = connectionSchema.parse(JSON.parse(await readFile(connectionPath, 'utf8')));
const agent = await StudyClient.connect(connection);
try {
  await agent.discover();
  const source = await agent.tool('codebook_source', {
    instanceId: connection.instanceId, path: sourcePath,
  }, repositorySourceSchema.extend({ instanceId: z.uuid() }));
  console.log(JSON.stringify(source, null, 2));
} finally {
  await agent.close();
}
NODE
```

## Recovery and resource semantics

| Situation | Recovery |
| --- | --- |
| Lost response or new transport, same server | Reinitialize, read `codebook_status` and the existing run. Reuse the original key only. Never retry a click with a new key automatically. |
| Server restart | Copy the new connection first. Old credentials fail before MCP; old instance IDs fail as `STALE_INSTANCE` under the new connection. Existing files persist, but execution is not restored. |
| `BUSY` | Inspect `nextActions` and readiness. One active run is allowed; a second click is not queued. |
| `STALE_PAUSE` | Read current state. Continue only if it is resumable, with its exact current arguments. Historical evidence cannot resume execution. |
| `STALE_PLAYBACK` | Read the current playback resource, preserve the selected study, and choose the next control with its new revision. Never recover by replaying application input. |
| `PLAYBACK_UNAVAILABLE` | Read the reason, repair or select available recorded evidence, then explicitly reload. Missing evidence is not a completed recording. |
| `SOURCE_CHANGED` | Read the captured source resource; the current editor file differs from it. |
| Repository source excluded, unavailable or changed | Rediscover eligible tracked paths, read their current bytes, and explicitly update citations. Retained book source stays readable. Do not bypass the repository boundary. |
| Book revision or intent conflict | Read the repository catalog/current book. Use a new intent key for a deliberately revised document; retry identical lost-response input with its original key. |
| Book/progress corruption or capacity | Preserve the affected files, repair the named storage problem, then explicitly retry. No history is deleted or silently replaced. |
| `EVIDENCE_UNAVAILABLE` or failed run | Inspect cause and available history, stop owned resources, and retain partial evidence. Missing images or persistence failures never imply complete success. |
| Missing prerequisite | Status names the dependency/configuration key. Correct it before deliberately starting another study. |
| Session capacity | Gracefully terminate unused MCP sessions. A client `DELETE` releases its transport only. It does not stop a study. |

GET `/mcp` returns 405; this service provides JSON POST responses and polled resources, with no standalone notification stream. The pinned SDK client supports this. Idle transport sessions expire after five minutes; live application execution has its own deadline.

Run resources distinguish current control state from historical snapshot/source/PNG/explanation references. Snapshot reads never create live pause authority. Events are paged (50/page) with a next URI and explicit detail truncation. Runtime source resources are sealed TS/JS/map bytes; they remain readable after the application and debugger exit. Repository reads accept only validated relative paths within the selected tracked-source boundary. No API accepts executable JavaScript, shell commands, arbitrary filesystem access or editor command names.

Resource identity is validated after the MCP SDK's URL normalization. Safe dot-segment aliases can resolve to the same canonical resource; they do not bypass instance/study/hash checks. Clients should follow returned canonical URIs.

Limits: 8 MCP sessions, 32 concurrent HTTP requests, 1 MiB + 64 KiB HTTP envelopes (separate from the 1 MiB book-document cap), 8 KiB headers, 5 s body reads; 1 active/16 retained runs per instance, no history eviction; 32 explanation intents/run, 8,192 characters and up to 10 distinct captured paths; each demo runtime source resource ≤1 MiB, PNG ≤8 MiB. Configured runtime source resources allow TypeScript ≤256 KiB, JavaScript ≤8 MiB and source maps ≤16 MiB; discovery and `codebook://help/repository-browser` expose these as `profile.limits.sourceBytes`. Evidence buffering is capped at 10,000 events / 4 MiB retained event bytes / 16 MiB pending writes. Overflow is an explicit failed run followed by owned cleanup.

The paired demo permits **20 seconds of active application time and 120 seconds wall time**, including setup. Checkout permits **20 seconds for setup, 20 seconds of active progress per action and 300 seconds wall time**. Confirmed pauses and the ready interval between checkout actions do not spend the checkout action budget; they still spend wall time. Forty-second inspection is tested; pauses past the wall deadline are history only. Completed and failed runs clean themselves even if the agent disappears. The fixed deadline is visible in each start receipt and run resource.
